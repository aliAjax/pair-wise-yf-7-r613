# 活字排版工坊

一个纯前端本地应用，用来维护字模库、在网格版面中落字、检查字模数量是否超用、保存草稿并导出PNG预览图。

直接打开 `index.html` 即可使用，也可以在本目录启动静态服务访问。

## 交接班编排（多窗口共用一台机器）

两人各自开窗口改同一张版面时，以"修订号 + 班次"防止后保存覆盖先保存：

- **领班次**：每个窗口启动时领到一份带修订号的班次（当班人可改名）。本班的落字、字模数量增减都只改工作副本，不直接生效。
- **提交班次（CAS）**：提交时携带基修订号比较并交换——修订号一致才写入，修订号 +1；两人同时提交时只有一个成功，另一个的班次立即退回。
- **撞班冲突**：退回的班次自动并入不冲突的格（含对方的新落字）；同一格两边选了不同字模时，该格高亮为冲突格，列出"本班选的字模 / 已确认的字模"，逐格选用（或一键全选本班 / 全选已确认）后重新提交。
- **字模数量更新**：任一字模的数量随提交确认后，其他未确认班次立刻采用新数量并重算用量，本班次退回待确认；本班新增、尚未落班的字模保留，本班未提交的数量改动退回。
- **草稿与导出**：保存草稿、导出 PNG 只认已确认班次（草稿带修订号戳），本班未落班的改动不会混入。
- **旧草稿接管**：无修订号的旧草稿显示为"旧稿"，点"单人接管"后作为一份单人班次挂到当前修订号上，提交即并入。
- **重领班次**：放弃本班未落班的全部改动，重新领取最新修订号的班次。

跨窗口实时同步使用 BroadcastChannel（不支持时自动退回 `storage` 事件）；班次工作副本存于会话存储，刷新窗口不丢；已确认文档存于本地存储。

### 双窗口自测

1. 启动静态服务（如 `python3 -m http.server`），开两个浏览器窗口，分别改当班人为"甲""乙"。
2. 两人各自落几个字，甲先提交（修订号 +1），乙再提交：乙看到班次退回、冲突格与两边选的字模。
3. 乙逐格裁决后重新提交，双方版面一致、互不丢字。
4. 甲修改某字模数量并提交，乙未确认班次立刻收到退回提示并按新数量重算。
5. 乙在未提交状态下保存草稿 / 导出，内容只含已确认版面。
